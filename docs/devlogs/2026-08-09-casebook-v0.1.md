# DevLog — 2026-08-09 — Evidence-backed Casebook v0.1

## Problem

AI coding agents accelerated delivery, but the valuable diagnosis, rejected hypotheses,
code paths, test evidence, and review decisions remained scattered across conversations
and local runs. A merged feature did not mean the operator could explain or rebuild it in
an interview.

## Evidence before change

The BuildLog dogfood run completed planning and writing but stopped at the evaluator with
`llm_json_invalid`. A later read-only diagnosis could locate the parser boundary and rule
out supported truncation, but the rejected raw response had not been retained. The exact
content-level failure therefore remained unknown. This was useful engineering evidence
and an equally useful learning case, but no product surface preserved both states.

## Hypotheses

- Preserving selected evidence with hashes would make later claims and practice artifacts
  integrity-checkable.
- Separating delivery and mastery would stop agent-completed work from being mistaken for
  human understanding.
- One exact next practice action would be more useful than another long retrospective.

Commercial demand beyond the founder remains unvalidated.

## Decision

Build a narrow local-first product slice named SoloScale Casebook v0.1:

```text
selected local evidence
→ byte-for-byte private archive + SHA-256 receipts
→ strict LearningCase
→ deterministic Interview Practice Packet
→ append-only Explain / Trace / Rebuild / Debug / Defend attempts
→ local Control Tower
```

The slice makes no LLM calls and does not scrape ChatGPT, Codex, Claude Code, or browser
history. Inputs are explicit so privacy and evidence boundaries remain inspectable.

## Alternatives considered

- Build the full hosted Control Tower immediately: rejected because authentication,
  tenancy, redaction, connectors, and billing do not validate the core learning loop.
- Generate interview answers automatically: rejected because it would deepen the exact
  understanding debt the product is meant to reduce.
- Store only summaries: rejected because a summary cannot prove the archived source was
  preserved unchanged.

## Implementation

- Added strict case, evidence, practice receipt, attempt, and mastery contracts.
- Added atomic case publication and byte-for-byte evidence archival.
- Added append-only practice attempts with sequential passing gates and regression support.
- Added metadata-only integrity verification.
- Added deterministic interview packets that omit raw evidence bodies and evidence source
  paths.
- Added a responsive, zero-JavaScript Control Tower with separate engineering and learning
  tracks, evidence integrity, five stages, and one exact next action.
- Added CLI commands: `case-create`, `case-attempt`, `case-status`, and
  `control-tower-build`.
- Added a sanitized Citation Feature example and local dogfood case. The unresolved
  BuildLog evaluator incident remains diagnostic evidence, not a falsely resolved case.

## Verification

- `pytest -q`: 143 passed.
- `ruff check .`: passed.
- `mypy src tests`: passed in strict mode.
- `python -m build`: isolated sdist and wheel builds passed.
- Real CLI dogfood created `source-grounded-citations` with two archived files; both SHA-256
  and byte-size checks passed.
- `case-status` reported `RESOLVED`, evidence `PASS`, learning `CAPTURED`, readiness `0/5`,
  and next action `EXPLAIN`.
- Browser checks at 1365×900 and 390×844 found no horizontal overflow, browser errors, or
  error overlay. Mobile reading order was corrected to Case → Current Focus → Tracks.
- Generated Markdown and HTML contained neither raw evidence bodies nor evidence-receipt
  source paths.
- Fresh-context review initially rejected the candidate on concrete privacy and durability
  failures: unsafe output targeting, permissive local modes, partial/ambiguous JSONL
  commits, post-commit retry ambiguity, managed-path symlink escape, legacy archive-name
  leakage, and missing-history reset. Each finding received a regression test and bounded
  remediation.
- The final fresh-context merge-gate verdict was `APPROVE` with `P0=0`, `P1=0`, and
  `P2=0`.

The local runtime and generated `.soloscale/` artifacts remain ignored and are not part of
the public Git diff.

## Result

The first complete local Casebook vertical slice works. It can preserve one real incident,
show where the operator is, and require an actual practice artifact before advancing.

The dogfood case intentionally remains at `0/5`: implementation evidence is complete, but
the operator has not yet supplied an unaided Explain receipt.

## Remaining risks

- Case framing and evidence selection are manual.
- v0.1 does not redact secrets or personal data; the operator must select safe inputs.
- JSONL is local single-writer storage, not a concurrent or tamper-evident ledger.
- Practice outcomes are self-assessed and do not grade semantic quality.
- Automatic capture, spaced repetition, resume generation, publishing, and SaaS are future
  hypotheses, not completed capabilities.
- Commercial value must be tested through observed use by at least five other heavy
  coding-agent users.

## Lesson

Agent throughput and human mastery are different state machines. A credible learning
product needs evidence receipts and deliberate retrieval practice, not another generated
confidence score.
