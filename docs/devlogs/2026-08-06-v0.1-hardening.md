# DevLog — 2026-08-06 — Harden v0.1 contracts and evidence

## Problem

The `dd2a5cd` starter implemented the basic route, handoff, event, and export path, but its pre-remediation baseline still had eight Ruff issues. Review also exposed contract and state-transition paths that needed stronger validation before the scaffold could be a credible foundation.

## Evidence before change

The [baseline DevLog](2026-08-06-v0.1-baseline.md) records eight passing tests, a passing type check and CLI demo, and eight Ruff issues at `dd2a5cd`.

## Hypotheses

- Strict, versioned contracts will reject ambiguous or unknown fields earlier.
- Evidence-backed transitions and explicit approval receipts will close state and approval bypasses.
- Persisted state continuity will make orchestration results easier to inspect and resume.
- Broader behavior, CLI, and adversarial tests will expose regressions that the starter suite could not.

## Decision

Harden the deterministic core before adding external execution. Preserve the original baseline, remediate its known quality failures, expand negative-path coverage, and verify the installed CLI and distributable package outside the repository working directory.

## Alternatives considered

- Add external service adapters first: rejected because weak local contracts would make later integrations harder to trust.
- Replace the baseline with only the green hardening result: rejected because it would erase the reason for the work.
- Treat configured CI as proof that CI passed: rejected because no public run receipt is available.

## Implementation

Revision `9fd720b`:

- added strict, versioned public contracts that reject unknown fields;
- required evidence-backed orchestration transitions and execution approval receipts;
- preserved state continuity and complete planning fields in execution packets;
- removed state and approval bypass paths;
- expanded behavior, adversarial, CLI, and orchestration coverage;
- made the installed demo independent of the current working directory;
- remediated the baseline Ruff findings;
- added package-build and broader quality checks to the CI configuration.

## Result

The known baseline lint failure is remediated at `9fd720b`, the local suite grew from 8 to 28 passing tests, strict typing covers source and tests, the installed demo works outside the repository, and the revision produces both distribution formats.

These are local implementation results. They do not establish that a public CI run passed, that a PR was independently reviewed, that anything was deployed, or that surface routing improves time, turns, tokens, cost, or quality.

## Remaining risks

- No public CI, PR, or deployment receipt is linked.
- v0.1 still does not invoke external execution surfaces.
- The first real routed feature and comparative efficiency measurement remain incomplete.
- The isolated build requires access to declared build dependencies when they are not already cached.
- Local terminal observations still need durable public receipts before launch claims are finalized.

## Lesson

Hardening evidence is most useful as a before-and-after chain: preserve the red baseline, tie the green result to a revision, and state which product outcomes remain unmeasured.
