# SoloScale Skill OS

**Date:** 2026-08-13
**Status:** Local candidate ready for human review

## Problem

Repeated SoloScale workflows existed as product code, long prompts, and operator memory.
Future tasks still needed to restate Evidence, editorial, visual, Career, Learning, and
publishing boundaries even though those capabilities already had typed contracts.

## Decision

Add a thin repo-scoped Skill registry over existing capabilities. A Skill is a bounded
versioned workflow, not a persona. Deterministic code normalizes a high-level request,
selects exact Skill versions, exposes human gates, and writes a private route receipt.
It does not execute a model or grant new domain authority.

Initial definitions remain `DRAFT` or `CANDIDATE`; none is `ACTIVE`. One successful Run
cannot silently promote or rewrite a Skill. Public, paid, credential, destructive,
migration, Git-history, and deployment actions remain explicit human gates.

## Implementation

- Added nine concise Skill packages, a JSON-compatible registry, Task templates, and native
  Skill metadata under `.agents/`.
- Added strict registry, Task Envelope, route, phase model, outcome-state, and Run Receipt
  contracts.
- Added deterministic Editorial, Career, Publishing, Evidence, and distillation routing.
- Added private non-overwriting route artifacts and receipts under `<data-root>/skills/`.
- Added `soloscale skill-list` and `soloscale skill-route` without changing existing task or
  domain commands.

## Truth boundary

A `ROUTED` receipt proves only that intake, selection, and private persistence completed.
It does not prove workflow completion, artifact generation, human approval, publication,
submission, or an observed external outcome. Those states remain separate fields.
